# Library 조회 범위와 클라이언트 캐시 개선

## 확인된 문제

기존 `GET /api/library`는 모든 일정의 주소·연락처·메모와 사진 통계를 반환했다. 사진 목록에는 페이지 제한이 있었지만 일정 상세에는 없었다. 클라이언트는 전체 메타데이터를 30초, 위치별 응답을 60초만 보관했고 일반 갱신에서 모든 위치의 캐시를 비웠다. 초기 URL 위치 복원 이전의 요청과 60초 주기 조회도 있었다.

## 변경한 조회 계약

| 요청 | 응답 범위 |
| --- | --- |
| 기본 조회 | 지역 카드와 집계, 일정 상세 없음 |
| `region` | 선택한 지역의 날짜 카드와 집계 |
| `region` + `date` | 일정 카드, 기본 60개·최대 100개와 다음 페이지 |
| `view=address` + `region` + `path` | 현재 주소 단계의 카드와 집계 |
| `q` | 서버 검색 결과 카드, 기본 60개·최대 100개 |
| `folder` | 선택한 일정의 상세와 사진 첫 페이지 |
| `folder` + `view=address` | 선택한 일정의 상세, 같은 주소의 다른 방문은 간단한 목록 정보, 사진은 통합 |
| `navigation=1` | 지역 이름과 선택한 지역의 날짜·일정 수 |
| `usageOnly=1` | 사용량·용량 예측 |
| `photosOnly=1` | 기존 사진 페이지 조회 계약 유지 |

목록에는 연락처·방문 메모·조사 비고를 포함하지 않는다. 모든 API는 기존 사용자 인증과 소유자 조건을 유지한다. SQL 집계는 `folder_stats`를 사용한다. 날짜의 일정 목록은 SQL에서 페이지를 제한한다. 주소 묶음과 한글·영문 혼합 검색은 기존 주소 분류 규칙을 유지하기 위해 서버에서 최소 목록 필드만 읽어 묶은 뒤 현재 페이지를 반환한다. 이 부분은 일정 수가 크게 늘면 별도 검색 인덱스 개선 대상이다.

## 상태 갱신

- 마운트된 보관함별 메모리 캐시: 5분, 최대 80개 요청 키. URL의 조회 범위와 사진 종류를 구분한다.
- 같은 요청이 진행 중이면 요청을 공유한다. 캐시가 유효한 폴더 왕복은 새 요청 없이 표시한다.
- URL 위치를 복원한 뒤 첫 요청을 보낸다. 검색은 250ms 지연하고 위치 이동 시 검색 상태를 함께 초기화한다.
- 사진·일정·비고 변경, 삭제, 재전송 후 관련 목록과 상세를 무효화한다. 백업 복원은 전체를 무효화한다.
- 더 불러온 사진·일정 페이지도 기본 위치 캐시에 합쳐서 보존한다.
- 60초 주기 조회를 제거했다. 오래된 위치 진입, 5분 이상 지난 창 복귀, 직접 새로고침에서 다시 확인한다.
- 로그아웃·인증 거부 시 캐시를 제거한다. 서버나 브라우저 영구 저장소에 응답 캐시를 공유하지 않는다.
- 다른 기기의 변경이 이미 열린 화면에 즉시 전파되는 방식은 아니다. 즉시 확인하려면 새로고침을 사용한다.

검색·주소 묶음의 일괄 삭제는 카드마다 전체 일정 ID를 내려보내지 않는다. 사용자가 삭제 대상을 확인할 때 선택 범위를 서버에서 ID로 변환하고, 그 확인된 ID로 기존 삭제 절차를 실행한다. 날짜별 개별 일정은 ID를 묶어서 확인한다. 기존 주소 책갈피는 카테고리를 포함한 경로로 보정한다.

## 측정

기존 응답의 일정 232개를 일회성 로컬 메모리 DB에 넣어 동일한 집계로 비교했다. 개인 자료와 원본 응답은 Git에서 제외된 `.sites-runtime/library-qa/`에만 보관한다.

| 조회 | 응답 크기 | 상세 일정 수 |
| --- | ---: | ---: |
| 기존 기본 조회 | 130,898 bytes | 232 |
| 변경 후 기본 조회 | 1,819 bytes | 0 |
| 선택한 날짜 (9개 일정) | 5,557 bytes | 0 |
| 선택한 일정 | 961 bytes | 1 |

기본 응답 본문은 98.6% 줄었다. 초기 사용량·탐색 목록 요청은 별도이며 이 수치에 포함하지 않는다. 원본 사진 파일을 복사한 시험이 아니므로 사진 전송 시간 또는 운영 환경 전체 지연 시간의 개선율을 뜻하지 않는다.

실제 로컬 브라우저에서 이미 읽은 일정과 상위 날짜를 4회 이동했을 때 추가 `library` 요청은 0건이었다. 서버 진단 로그는 요청 범위·상태·본문 길이만 기록하며 운영 코드에 포함하지 않는다. 검색, 주소 계층, 선택 일정 상세, 삭제 확인 미리보기까지 확인했으며 사용자 자료를 삭제하지 않았다.

회귀 검증은 별도 API 통합 테스트로 요약 응답·페이지 경계·상세 개인정보 범위·검색·선택 삭제·기존 주소 경로를 확인하고, 실제 로컬 HTTP 서버로 요청 공유·위치 재사용·캐시 무효화·401 시 폐기를 확인한다. ZIP·백업·인증·일정 수정의 기존 통합 검증도 유지한다.

2026-10-10 사용자 요청에 따라 운영에 반영했다. Worker 버전은 `238127a8-d986-4b3a-9040-71637aa5b10c`, 주소는 https://hanaparttime.isacc7224.workers.dev 이다. 배포 직전 새로 실행한 타입·린트·빌드, 단위 테스트 156개, 통합 검사 11개가 통과했다. 검증·배포 소스 SHA-256은 `a38a1b372556d634c6b8720e7bfba9360c09710624ce8e70df9dd3447d338d75`다.

운영 API에서도 기본 응답 1,819바이트·지역 카드 5개·전체 상세 0개를 확인했다. 날짜 페이지 제한과 다음 페이지, 선택한 일정 상세, 주소 묶음의 개인정보 범위, 서버 검색, 삭제 확인 미리보기, 로그인·갱신·로그아웃 후 기존 토큰 거부를 검증했다. 새 workspace/CSS 파일도 로컬 빌드와 바이트가 일치했다. 배포 전후 일정 232개·사진/도면 1,085개·일정표 원본 35개·도면 초안 1개가 유지됐다. OCR/도면 AI 추론과 사용자 자료 삭제는 실행하지 않았다. Git 반영 브랜치는 `external-cloudflare`다.
