## 동작

- JWT로 변경하지 않고 서버에서 폐기 가능한 불투명 토큰을 사용한다. 액세스는 기존 `__Host-fieldnote_session`, 리프레시는 `__Host-hana_refresh` HttpOnly/Secure/SameSite=Lax/Path=/ 쿠키다. 응답 JSON이나 localStorage에 토큰을 넣지 않는다.
- 액세스 15분 만료 후 다음 페이지/API/사진/ZIP 원본 요청에서 Worker가 리프레시를 검증하고 동일 요청을 계속 처리한다. 업로드 본문을 다시 보내거나 중복 실행하지 않는다. 90일 만료는 리프레시 교체 시점부터 다시 계산된다.
- 외부 공유 링크의 정상 GET 문서 탐색도 갱신을 허용한다. 외부 사이트의 변경 요청은 기존 Origin/Fetch Metadata 검사를 유지한다. 명시적 갱신은 `POST /api/session/refresh`이며 동일 출처만 허용한다.
- DB `site_refresh_sessions`는 기기별 토큰 묶음 ID, 현재/직전 리프레시 해시, 직전 토큰 허용 시각, 계정 버전, 만료 시각을 보관한다. `site_sessions.family_id`로 액세스 토큰을 연결한다. 두 토큰 모두 원문을 DB에 저장하지 않는다.
- 갱신은 원자적 조건부 갱신과 D1 batch를 사용한다. 60초 동시 요청 허용 구간에는 직전 토큰으로 동일 후속 토큰을 반환하고 추가 세대 교체를 하지 않는다. 후속 토큰은 기존 서버 비밀키를 사용하는 목적별 HMAC-SHA256으로 도출하므로 원문 저장 없이 동시 요청의 결과를 맞춘다. 구간이 지난 직전 토큰은 거부한다.
- 로그아웃은 액세스 또는 현재/직전 리프레시 증명으로 해당 기기의 묶음과 연결된 액세스 레코드를 삭제하고 쿠키 두 개를 Max-Age=0으로 지운다. 리프레시만 남아 있어도 로그아웃 가능하다. 다른 기기의 세션은 유지한다.
- 계정/비밀번호 재설정은 버전을 올리고 이전 버전 액세스·리프레시를 모두 폐기한다. 삭제/재설정과 갱신이 경합해도 삭제된 묶음에 액세스 토큰을 다시 생성하지 않는다.
- 기존 유효한 7일 세션은 정상 접근 시 새 방식으로 전환하고 기존 증명의 유효기간도 최대 15분으로 줄인다. 이미 만료된 기존 세션은 다시 로그인해야 한다.
- 만료된 액세스 증명은 로그아웃 경합 처리를 위해 잠시 남기되, 로그인/갱신 시 만료 후 24시간이 지난 레코드를 정리한다. 유효기간이 지난 증명으로 자료를 조회할 수는 없다.

## 경계

90일 동안 사용하지 않거나 브라우저 쿠키를 삭제한 경우에는 재로그인이 필요하다. 갱신 중 서버/네트워크 장애는 실패로 반환하며 쿠키를 임의로 삭제하지 않는다. 동시 응답이 로그아웃 뒤 도착해 브라우저에 오래된 쿠키가 남더라도 서버 레코드가 삭제되어 재사용할 수 없다.
