# 기존 폴더의 조사 인원과 사진 다운로드 확인

2026-10-14 요청: 과거 폴더의 조사 인원을 관리자가 지정하고, 사진을 내려받을 때 완료로 표시할지 직접 선택한다. 다운로드 상태는 개인별이 아닌 팀 공용으로 저장하며 확인한 사람과 시간을 표시한다. 이 변경은 로컬 구현으로 진행한다.

## 사용

관리자는 개별 일정의 ‘조사 인원 설정’에서 등록된 계정을 여러 명 선택한다. 이름·아이디 검색과 목록 추가 조회를 지원한다. 자동 작업 기록에 없는 선택 인원에는 ‘관리자 지정’이 붙는다. 자동 기록에서 확인되는 사람이 중복 지정되면 한 명으로 표시하며, 수동 지정을 해제해도 그 사람의 실제 작업 기록은 남는다. 지정은 과거 사진 작성자·개인 조사 보고 내용을 변경하지 않는다.

ZIP 저장 요청이 성공한 뒤 ‘완료로 표시 / 표시하지 않음’ 버튼을 제공한다. 브라우저가 기기 저장 완료 여부를 직접 알려주지 못하는 방식에서는 다운로드 목록과 파일을 사용자가 확인한 뒤 선택한다. 취소·원본 오류·저장 실패는 완료 표시를 자동으로 만들지 않는다.

폴더 목록과 개별 일정에 사진 다운로드 상태를 표시한다. 완료로 표시하면 확인자와 한국 시간 기준 확인 시각이 남는다. 사진 추가·삭제 이후에는 기존 확인 기록을 유지하면서 ‘사진 변경됨 · 다시 다운로드 필요’로 표시한다. 조사 완료 상태와 사진 다운로드 상태는 별개다. 완료 표시 해제는 로그인한 팀원이 진행할 수 있다.

## 데이터와 검증 기준

- D1 `0021_folder_operations.sql`: 수동 인원/수정 버전, 사진 목록 버전, 다운로드 확인 기록과 짧은 수명 ZIP 확인 정보. 기존 관리자/자료/세션은 유지한다.
- 수동 지정은 관리자 권한과 동일 Origin을 검사한다. 두 화면의 동시 수정은 버전으로 거부하며 검색·추가 조회가 편집 시작 버전을 바꾸지 않는다.
- 사진만 목록 버전을 바꾼다. 도면 추가는 현장 사진 다운로드 확인에 영향을 주지 않는다.
- ZIP 확인 정보에는 해당 일정의 사진 목록 버전·전체 장수·전송 범위를 저장한다. 일부 분할 파일만 받은 경우나 같은 분할을 반복한 경우는 전체 완료가 되지 않는다. 사진이 달라진 상태도 거부한다.
- 사진 ID 전체를 하나의 DB 값에 합치지 않는다. 범위를 병합해 확인하고 500개 일정씩 저장·갱신하여 큰 분할 다운로드의 DB 값 크기를 제한한다.
- 표시 변경은 원본 읽기나 새 썸네일을 만들지 않는다. 기존 목록의 범위 제한 조회와 캐시를 유지하고 관련 날짜/주소 보기만 무효화한다. 응답 중 이동했다면 현재 범위의 요청을 갱신한다.
- 수동 인원과 다운로드 확인은 기존 형식 1 백업의 선택 필드로 보존한다. 예전 백업 해시를 유지하며 복원한 확인자·지정자 출처를 구분한다. 임시 ZIP 확인 정보와 작업 이력 목록 자체는 파일 백업에 포함하지 않는다.

로컬 통합 검증은 관리자/팀원·다른 팀·동일 Origin 경계, 과거 조사 결과 보존, 명시적 확인, 완료 해제 충돌, 사진 추가 이후의 오래된 확인 거부, 분할 파일 전체 범위와 백업·복원을 포함한다. 비공개 합성 자료·실행 로그는 `.sites-runtime/personnel-qa/`에 보관한다.
